# 历史
<<>>从22年初，chatGPT突然爆火，到现在4年多的时间，AI几乎已经改变了编程方式。个人体感上来说，有如下比较大的**跃迁点**：
1. 2021年初，GitHub copilot横空出世，当我尝试输入`function quickSort(`后，惊为天人。但彼时只能补全一些基本逻辑。
2. 2022年初，chatGPT出现了，全网都是千奇百怪的和chatGPT聊天的截图，而国内注册方式是购买一个印尼sms接收服务。大家对“人工智能”的认知有了大改观。
3. 2023-2024，AI持续发展，生图/视频，AI短片开始崭露头角。编程领域，有了cursor这种把AI x IDE做到惊艳的产品，生产力大幅提升。
4. 2025~至今，模型跑分混战，Agentic，MCP，Claude Code，Openclaw，skills，harness，几乎每几个月就有新奇的玩法问世，AI的coding能力已经达到了生产可用状态，完成一个需求已是和coding agent聊聊天的事情。

# vibe coding
<<>>从25年开始，我的工作方式已随着AI能力变强（现阶段是fable5）而逐渐改变。

<<>>最开始是，我根据需求制定大致方案 -> 让AI调研整理出完整开发计划 -> 分步骤让AI独立完成。此时还不是完全相信AI，自己必须验证 & review。
<<>>而现在，已经由AI帮我完成几乎全部的编码工作，自己只提供需求，上下文，然后和AI讨论方案，最后让AI自己分工，自己开sub-agent开发，自己合并pr到feature分支，自己去模拟点击验收。我要做的就是简要看一下方案是否合理，AI是否完全理解了我的意思。几乎不再review代码。

---

<<>>虽然但是，合理使用AI，才能发挥出最大的潜力。就我的个人经验来看，如下几件事情最为重要：
* 改变看法，把编码工作全部交给AI，自己关注架构上的事情。
* 确保自己和AI沟通完善，AI完全理解自己的需求，自己也知道AI将要如何开发。进一步来说，如果没有AI的话，自己花更多的时间也能开发出来。只有达到这种程度，才可放心让AI去做。
* 动手之前，先制定计划，拆分子需求，做好项目进度管理，例如让AI每次做出改变时，都同步issue,milestone。
* 让多个AI分工。AI的上下文是有限的，所以需要一个地方做进度管理，把单独的子需求交给单独的AI做。拆得越细越好，自己只做全局统筹工作，以及关键节点验收。
